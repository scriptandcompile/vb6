# Catalog sources, provenance, and generation

The catalog is assembled from distinct VB6R source artifacts rather than a
single aggregate file:

- `data/opcodes.csv`: six full dispatch tables with opcode names, sizes,
  operand formats, stack/x87 effects, memory/object effects, semantic
  categories, and handler/RVA notes.
- `data/OPCODE-MATRIX.csv`: one row per table slot, including M1's
  `INVALID_CONFIRMED` and `OUT_OF_PHYSICAL_TABLE` classifications and
  documented-form status.
- `data/opcode-forms.json`: evidence-qualified instruction forms and length
  rules generated by the M1 form generator.
- `data/dispatch-map-v2.json`: physical dispatch slot mapping evidence.

`build.rs` consumes the two CSVs locally and emits Rust static tables. The
generation logic is dependency-free and never reads from another checkout.
The source-side generators are retained under `scripts/` for provenance and
reproducibility; they are research tools and do not run as crate build steps.

The Rust catalog/decoder and the table build logic are original VB6R-derived
work. The opcode CSV and supporting material include data from
`ATRAPSLLC/visualbasic-rs` 0.5.0, revision
`7885bb7096694c94f94801f2db4cb6e086fbee57`, under Apache-2.0. The applicable
license and source notice are retained in this crate. No VM handlers, runtime,
or compiler modules are imported.
